# Codex 共享账号额度监控服务规范

## 1. 目标

为一个由多人共享的 Codex 账号提供本地监控服务。服务直接读取 Codex 软件维护的 `auth.json`，查询账号真实额度窗口，记录每日使用情况，并在达到约定阈值时发送邮件。

本服务只监控和告警，不拦截请求、不停用账号、不修改 `auth.json`。

## 2. 使用规范

1. 周额度以 Codex 上游返回的周窗口为准，完整窗口记作 100%。
2. 默认时区为 `Asia/Shanghai`。
3. 周一至周五为工作日，每日基础上限为周额度的 16%，五天基础配置合计 80%；这是结转前的基础值，不是会因超用而倒扣的硬性额度池。
4. 某个工作日未用完的额度会平均分配给同一自然周内后续工作日；当天上限确定后不再随当天使用量变化。
5. 工作日超用只会使当天超额，不会产生负结余或扣减后续工作日的 16% 基础额度。没有历史采集记录的日期不会被当成“使用 0%”产生新结余；此前已经平分给该日期的份额也不会再次分配。
6. 工作日结余不进入周末，也不跨自然周结转。
7. 周六、周日为非工作日，每日建议最高使用周额度的 10%。
8. 法定节假日和调休首版不自动识别。
9. 当日使用达到当日上限的 80% 时进入“预警”状态。
10. 当日使用达到当日上限的 100% 时进入“超额”状态。
11. 预警和超额仅用于提醒；服务不会阻止账号继续使用。
12. 所有成员应避免在已进入“预警”或“超额”状态后发起非必要的大型任务。
13. 每日边界按配置时区的自然日计算。

## 3. 数据来源

### 3.1 账号额度

服务每小时重新读取一次 `auth.json`，提取 `access_token` 和 `account_id`，请求：

```http
GET https://chatgpt.com/backend-api/wham/usage
Authorization: Bearer <access_token>
chatgpt-account-id: <account_id>
originator: codex_cli_rs
Accept: application/json
```

周窗口由 `limit_window_seconds >= 86400` 识别。周已用比例、剩余比例和计划重置时间均以上游响应为准。

### 3.2 重置雷达

服务读取 `https://codex-resets.com/api/resets`，展示最近一次全局额外重置公告，以及当前有效的 24 小时重置概率预测。预测使用接口 `watch` 对象中的 `reset_chance_24h`、`observed_at`、`expires_at` 和来源推文；预测过期或概率不在 0–100 范围时不展示。

重置概率是 Codex Resets 的第三方 AI 估算，不是 OpenAI 的额度承诺，不改变每日上限、账号额度、告警状态或计划重置时间。账号真实额度始终以 `/wham/usage` 为准。

当雷达出现新公告时，服务会在下一次采集中重新核对账号额度。只有账号额度实际下降或额度 epoch 改变，才记录“已确认重置”。

## 4. 每日使用计算

1. 每次成功采集保存周已用比例快照。
2. 同一额度 epoch 内，本次已用比例减去上次已用比例，作为新增使用量。
3. 如果 `reset_at` 改变或已用比例明显下降，则开启新 epoch；重置前已累计的当日用量仍保留，新 epoch 的已用比例继续累加到当天。
4. 跨日时使用零点前后的最近快照计算首个增量。
5. 由于采集周期为一小时，页面数据最多可能延迟约一小时。
6. 采集失败时保留最后一次成功数据并标记为过期，不把额度误设为 0% 或 100%。
7. 上游 `reset_at` 在 60 秒以内的小幅变化视为同一 epoch；只有变化超过容差或已用比例明显下降时才确认重置。
8. 服务启动时从不可变快照重建每日汇总，并移除已不符合阈值的派生告警，以便修复旧版本产生的错误汇总。

## 5. 邮件规则

以下邮件对同一自然日、同一事件最多发送一次：

1. 当日用量达到当日上限的 80%。
2. 当日用量达到当日上限的 100%。
3. 账号额度连续采集失败 3 次。
4. 全局重置公告经账号额度变化确认生效。

SMTP 未配置完整时，事件仍写入数据库和页面，但邮件状态标为“未配置”。

## 6. 页面

页面至少展示：

- 当前状态：正常、预警、超额、数据过期或待配置。
- 周已用/剩余比例、周窗口重置时间和倒计时。
- 今日已用、今日上限、阈值进度。
- 最近 7 天每日用量与状态。
- 最近一次成功采集时间和连续失败次数。
- 当前有效的未来 24 小时重置概率、有效期、预测说明及来源链接。
- 最近一次全局重置公告及来源链接。
- 手动刷新按钮，30 秒内只允许触发一次。

邮箱、用户 ID 和 Account ID 只允许脱敏展示。Token 和原始 `auth.json` 永不进入浏览器、数据库或普通日志。

## 7. 安全边界

- 默认只监听 `127.0.0.1`。
- `auth.json` 只读；Token 刷新由 Codex 软件负责。
- 服务不输出 Authorization 请求头或上游原始认证错误正文。
- SMTP 密码只通过环境变量读取。
- 手动刷新不返回凭证和上游原始响应。

## 8. 不在首版范围

- 多账号。
- 请求代理、流量拦截和账号自动停用。
- 修改或刷新 `auth.json`。
- 自动使用 banked reset。
- 法定节假日和调休日历。
- 用户登录、权限系统和公网部署。
- 逐用户或逐请求的额度归因。
